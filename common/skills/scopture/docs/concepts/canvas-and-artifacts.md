# Canvas and Artifacts (/docs/concepts/canvas-and-artifacts)



## The Canvas as a Review Surface [#the-canvas-as-a-review-surface]

Scopture opens a drawing as an infinite canvas where project artifacts can be arranged beside the requirements, explanations, and review activity that qualify them. The canvas is the shared application surface for drawing, navigation, inspection, and collaboration; it is not a replacement for the specialist tools that authored the source material.

Use Scopture’s search, layers, groups, grids, snapping, measurements, and unit controls to move between the overview of a project and the detail being reviewed. Frames provide named visual regions, while plots identify deliberate output areas for presentation and export.

## Working with Artifacts [#working-with-artifacts]

Scopture can place 2D geometry, annotations, images, PDFs, documents, web references, and engineering models in the same drawing. In the application, the important distinction is how each artifact participates in review:

| Review need                  | Scopture behavior                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| Explain or mark up           | Draw, measure, label, connect, and annotate directly on the canvas                              |
| Provide evidence             | Position source sheets, reports, images, documents, and references beside the work they support |
| Inspect engineering geometry | Open a model element in its dedicated interactive environment                                   |
| Organize the review          | Use frames, layers, groups, and search to control context and navigation                        |
| Prepare an output            | Use plots or a selected canvas region to define what should be exported                         |

The underlying element types, relationships, and storage rules belong to the Duc format. See [Elements](https://duc.ducflair.com/docs/concepts/elements/overview), [Document Elements](https://duc.ducflair.com/docs/concepts/elements/document-element), [Plot Elements](https://duc.ducflair.com/docs/concepts/elements/plot-element), and [Blocks](https://duc.ducflair.com/docs/concepts/elements/blocks) in the Duc documentation.

## Model Review in Scopture [#model-review-in-scopture]

On the canvas, a model remains positioned alongside the rest of the project context. Its thumbnail represents the current generated output. Opening it in **Model Open mode** selects the viewer recorded in that output: parametric or IFC 3D, DXF 2D, image, SVG, PDF, or table. The element keeps its identity and canvas position when the output type changes.

The 3D viewer provides model selection, hierarchy navigation, camera controls, measurement, sectioning, display and material controls, and saved viewpoints. PDF output provides page navigation, while image, SVG, and table outputs open in their corresponding viewers.

Python models declare their result with `emit_output(...)`. Scopture stores the generated bytes as a referenced external file, together with the output kind, content and input fingerprints, and generation metadata. The properties panel shows **fresh**, **stale**, **missing**, or **failed** output. Changes to source code, parameters, dependency modules, or external inputs trigger cache and thumbnail regeneration when local or authorized cloud execution is available.

Use `get_svg_from_mermaid(source)` when your [Model Element outputs a Mermaid diagram](/docs/automation/python-sandbox#emit-a-mermaid-diagram).

An issue created during model inspection can return a reviewer to the relevant model location and viewing context. This connects a detailed geometry discussion back to the same issue and decision workflow used elsewhere in the drawing.

For supported model sources, Python output contracts, external-file relationships, and stored viewer state, see [Model Elements](https://duc.ducflair.com/docs/concepts/elements/model-element) in the Duc documentation.

## Mermaid in Typst Documents [#mermaid-in-typst-documents]

In a Scopture Document Element, import the bundled `mermaid` function and pass it Mermaid source. The diagram renders as vector artwork in the preview and exported PDF.

```typst
#import "/scopture/mermaid.typ": mermaid

#mermaid(
  "flowchart LR\n  A[Plan] --> B[Build]\n  B --> C[Review]",
  width: 80%,
  alt: "Plan, build, then review",
)
```

Omit `css:` to use the Scopture theme. To override it, pass inline Pele CSS variables such as `css: "--pele-surface: #e5eeff; --pele-border: #2457a6;"`. If the diagram is invalid, the document compiler reports the Mermaid diagnostic. The import is provided by Scopture’s document compiler.
